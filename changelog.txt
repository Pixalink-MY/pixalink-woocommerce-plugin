*** Pixalink Loyalty for WooCommerce Changelog ***

= 1.0.3 - 2026-11-06 =
* Add - Member portal sign-in over OAuth 2.1. When the heartbeat advertises it (`oauth`: authorize, token and revocation endpoints, S256 PKCE, the `profile` and `store:link` scopes), the store provisions its own OAuth client (`POST connection/oauth-client`, for `{home}/?pixalink_oauth=callback`; the client secret is stored encrypted) and "Sign in from Customer Portal" goes to the member portal's authorize page instead of the ticket page. The member signs in there the way the merchant set the portal up (WhatsApp inverse OTP or a code) and comes back to the store's callback, which checks the state kept in an encrypted, HttpOnly, SameSite=Lax ten-minute cookie, exchanges the code (form-encoded, HTTP Basic, PKCE verifier) and redeems the access token with `POST customers` (`verified_via: oauth`); Pixalink revokes the token there, so the store keeps none. Signing in, account creation and the staff refusal are exactly as for a portal ticket. Without `oauth` in the heartbeat, or until the client is provisioned, the ticket flow is unchanged.
* Add - "Verify with WhatsApp" for logged-in shoppers who have not verified yet, on My Account › Loyalty (above the one-time code form, which stays as "Or get a code by WhatsApp or SMS") and on the dashboard card. It runs the same OAuth sign-in (`admin-post.php?action=pixalink_loyalty_portal_sign_in&intent=verify`) and links the account on return without a second confirmation, with "Your account is now linked to your loyalty membership." on the Loyalty tab. Offered only over OAuth, while "Sign in from Customer Portal" is on and the store is connected, and never to staff or to an account that is already linked. An account linked to a different member is never switched (a notice says so); the same member changes nothing. The checkout's "Verify now" still opens the Loyalty tab, where both options are.
* Tweak - Template versions: `myaccount/link-account.php` and `myaccount/dashboard-card.php` are now 1.0.3 (new `$verify_url` variable); themes that override them should update their copies to show "Verify with WhatsApp".
* Dev - Contract: heartbeat `oauth`; `connection-oauth-client.request.json` / `.response.json`; `customers-create.request.json` gains the `oauth` branch (`oauth_access_token`, never with a ticket or phone) and the 410 `oauth_token_invalid`; `common.json` `verified_via` gains `oauth`; new `oauth-authorize.query.json`, `oauth-callback.query.json`, `oauth-token.request.json`, `oauth-token.response.json`, `oauth-error.response.json`. The fake server serves the oauth-client and token endpoints.
* Dev - New `Oauth\Capability`, `Oauth\ClientCredentials`, `Oauth\AuthorizationRequest`, `Oauth\CallbackHandler`, `Api\Resources\Oauth` and `Api\Client::post_form()` (form-encoded, absolute URL, HTTP Basic, unsigned). Linking and signing in after a portal proof moved from `SsoLanding` to `Identity\MemberLanding`, shared by the ticket and OAuth paths. `Link::VIA_OAUTH`, `Customers::oauth_payload()`, `CustomerLinker::redeem_oauth()`. New `PortalSignIn::can_verify()` and `PortalSignIn::verify_url()`; `AccountView` and `DashboardCard` take an optional `PortalSignIn`.

= 1.0.2 - 2026-11-05 =
* Fix - After the outlet API key in wp-config.php is swapped for another outlet's, WooCommerce › Settings › Pixalink Loyalty no longer shows the previous merchant's organisation name. The heartbeat names the outlet only, so when it reports another outlet the plugin now looks the organisation up (`GET outlet`) and records both; if that lookup fails, the record is left as it was and the next heartbeat retries.
* Dev - Plugin Check no longer warns about direct database calls in the event outbox (`EventRepository::prune()` and `update()`): a bare `phpcs:enable` had switched the file's documented custom-table exemption back off.

= 1.0.1 - 2026-11-05 =
* Security - Loyalty output from the `[pixalink_loyalty_summary]` and `[pixalink_loyalty_qr]` shortcodes, the My Account Loyalty tab and dashboard card, the classic checkout panel and the portal sign-in button is now passed through `wp_kses()` with an explicit allow-list (`Support\Html::allowed()`), including output from theme template overrides.
* Security - The loyalty phone number and marketing-consent fields on the registration and Account details forms are only read when that form's own WooCommerce nonce verifies.
* Tweak - The "connect your store" reminder now shows only on the Plugins screen, not on every admin page.
* Dev - CI no longer runs the WordPress trunk / WooCommerce pre-release integration environment; released versions only.

= 1.0.0 - 2026-10-27 =
* Add - Plugin scaffold: requirements checks (PHP 8.1, sodium, WooCommerce 11.0+), HPOS and Cart & Checkout blocks compatibility declarations.
* Add - Install lifecycle: activation seeds options, deactivation unschedules work, opt-in data removal on uninstall.
* Add - Support layer: encrypted credentials (sodium secretbox), masked WooCommerce logging, RFC 4122 UUIDs, money helpers, server-aligned clock.
* Add - Signed Pixalink Commerce API client with timestamp-skew recovery and the Connect resource.
* Add - WooCommerce › Settings › Pixalink Loyalty: connect an existing Pixalink account (hosted sign-in with PKCE) or paste an outlet API key, request access, test and disconnect.
* Add - Six-hourly connection heartbeat with remote feature switches, clock alignment and a "reconnect" state when Pixalink rejects the key.
* Add - Detects old Pixalink WooCommerce webhooks and offers to pause them when connecting.
* Add - Admin notices for a missing connection, a rejected key, an outdated plugin, an inactive Pixalink account and disabled coupons.
* Add - Loyalty phone number (stored in international format) and a separate, unticked marketing-consent box at checkout (Checkout block and classic), registration and Account details; the wording shown is recorded as a hash with every answer.
* Add - My Account › Loyalty: phone verification with a one-time code (WhatsApp or SMS), points, credits, tier, vouchers, memberships, recent activity and a member QR code; `[pixalink_loyalty_summary]` and `[pixalink_loyalty_qr]` shortcodes.
* Add - Sign-in from the Pixalink member portal (`pixalink_sso` links), customer updates to Pixalink when a shopper changes their phone or consent, and a signed webhook from Pixalink that refreshes balances and records withdrawn consent.
* Add - Personal data export and erasure for the loyalty account data, and suggested privacy policy text.
* Add - Vouchers, points and credits at checkout as virtual WooCommerce coupons, priced by a Pixalink quote, in the Checkout block (order summary panel, relabelled coupon chips) and the classic checkout (loyalty panel); only phone-verified members can use them.
* Add - Points, credits and vouchers are held when the order is placed and released when payment fails, the order is cancelled or it is abandoned (15-minute sweep).
* Add - Order-received page: points earned or when they will be added, and the rewards the order used; order screen: held and settled redemptions.
* Add - WooCommerce › Settings › Pixalink Loyalty › Checkout: credits toggle; each toggle shows when Pixalink switched the feature off.
* Add - My Account dashboard: a loyalty card with points, the next expiry, tier progress and vouchers ready, or a link to verify on the Loyalty tab; "Dashboard summary" setting under My Account (on by default).
* Fix - A Pixalink portal link opened while signed in as staff (editor, shop manager, administrator) no longer links that account to the member: nothing is linked or signed in, a notice says why, and `pixalink_loyalty_sso_refused_staff` fires. Staff accounts cannot be linked by a one-time code or a guest link moved at login either.
* Fix - A member the portal recognises but who stays a guest (store registration off, or no e-mail address) now sees a notice that they will earn points on this visit, with how to create an account; the Loyalty tab login form and `[pixalink_loyalty_summary]` say the same.
* Add - "Match your member portal" under WooCommerce › Settings › Pixalink Loyalty › My Account (on by default): My Account and both checkouts use the member portal's logo and colours from the heartbeat's `branding`, as CSS custom properties (`--pxl-primary`, `--pxl-on-primary`, `--pxl-ink`, `--pxl-accent`, `--pxl-tier`) scoped to the plugin's own wrappers; off, the same layout takes the theme's colours.
* Add - My Account › Loyalty redesigned: a member card (portal logo or name, tier with its colour, points, credits, the next points to expire, tier progress, member name and the member code behind "Show member code"), vouchers as tickets marked "Use at checkout" or "In store only", memberships, recent activity with signed point changes, and empty states; the dashboard card is a compact member card; a tidier phone verification form.
* Add - Portal buttons open the Pixalink member portal signed in for verified members: "View all rewards", "Full points history", "Credits" (while credits are on) and "Open member portal" go through `admin-post.php?action=pixalink_loyalty_open_portal`, which asks Pixalink for a single-use link at the click (`POST customers/{id}/portal-session`) and redirects with no-cache headers and `Referrer-Policy: no-referrer`; anything unexpected falls back to the signed-out portal. New action `pixalink_loyalty_portal_handoff` (user id, destination, outcome).
* Tweak - Checkout loyalty panel (Checkout block and classic): portal colours on its buttons, points slider and applied voucher, and compact buttons.
* Tweak - Template versions: `myaccount/loyalty.php`, `myaccount/dashboard-card.php`, `myaccount/link-account.php` and `checkout/loyalty-panel.php` are now 0.3.0; themes that override them should update their copies.
* Add - "Sign in from Customer Portal" under the My Account and classic checkout login forms (not the Checkout block, which has no login form), in the portal's logo and colours while "Match your member portal" is on. It goes through `admin-post.php?action=pixalink_loyalty_portal_sign_in`, which keeps a random state in the `pixalink_loyalty_sso_state` cookie (HttpOnly, SameSite=Lax, Secure on https, 10 minutes) and sends the browser (303, no cache, no Referer) to the heartbeat's `branding.sign_in_url` with `return` and `state`; the portal comes back with a `pixalink_sso` ticket, redeemed with `sso_state` from the cookie, which is then cleared. Shown only to logged-out shoppers while the store is connected and the heartbeat names a sign-in page on the portal's host.
* Add - "Sign in from Customer Portal" setting under WooCommerce › Settings › Pixalink Loyalty › My Account (`pixalink_loyalty_portal_sign_in`, on by default). A member who signs in with the button gets a customer account even with store registration off, as long as Pixalink has their e-mail address; without one they stay a recognised guest. The portal's Order links are unchanged. `pixalink_loyalty_sso_create_account` gets a third argument, whether the sign-in started from the button.
* Add - New template `global/portal-sign-in.php` (0.3.0) and stylesheet `assets/css/sign-in.css`; the button reads `--pxl-primary`, `--pxl-on-primary` and `--pxl-ink` on `.pixalink-loyalty-sign-in`.
* Fix - A portal button clicked after the store session ended no longer gets WordPress's blank 400: it goes to the My Account login form with `redirect_to` back to the Loyalty tab, without any call to Pixalink.
* Add - A store Pixalink staff paused (heartbeat `status: commerce_paused`, or 403 `commerce_paused` from any other call) keeps its connection but switches loyalty off at once: no vouchers or points at checkout, no balances, vouchers or verification form in My Account (one line says rewards are paused, and members stay verified), and no points promise on the order-received page. Order updates wait in the outbox without using up attempts and are sent automatically when a heartbeat reports the store active again. An admin notice, the event delivery panel, Site Health and "Test connection" say "Pixalink has paused this store. Points and vouchers are off until Pixalink turns it back on. Contact Pixalink support." New actions `pixalink_loyalty_commerce_paused` (request path) and `pixalink_loyalty_heartbeat_received` (heartbeat response); `pixalink_loyalty_delivery_paused` can pass `commerce_paused`.
* Fix - A 403 about the Pixalink account (subscription inactive, integration not enabled, store paused) on the member summary no longer unlinks the member's verified phone.
* Fix - The heartbeat reports the outbox to Pixalink (updates waiting, failed, oldest waiting); it always reported none.
* Add - Order and customer updates are sent to Pixalink at the end of the request that recorded them, after the response has gone to the browser (`fastcgi_finish_request()` or `litespeed_finish_request()`), instead of waiting for Action Scheduler, which runs on WP-Cron and so only when the store gets visits. The outbox and its Action Scheduler action stay the fallback: the attempt claims the row like a queue worker (never sent twice), skips an event while an earlier one of the same order is still open, uses a 5-second timeout, records a failure with the normal retry and backoff, stops at the first failure, sends at most 10 events per request, and is skipped while delivery is paused. Off under WP-Cron, WP-CLI and on servers that cannot finish the response early; new filter `pixalink_loyalty_send_events_immediately`. `Client::send_event()` takes an optional timeout.
* Add - The event delivery panel warns when an update that is not retrying has waited more than 5 minutes, and suggests a server cron job.
* Fix - Order and customer updates no longer keep going to the previous outlet after the store is reconnected to another one (Pixalink rejected them with 422 "The outlet id must be the outlet the API key belongs to." until they went dead). The cached outlet id now records a fingerprint of the API key and API base it was looked up for (a SHA-256 hash, never the key), and is not used once the key in wp-config.php (`PIXALINK_LOYALTY_API_KEY`) or the API base changes; it is also forgotten when a heartbeat reports another outlet and whenever a connection is recorded, including adopting the wp-config.php key. New action `pixalink_loyalty_credentials_changed` (after a connection is recorded). Updates already recorded for the old outlet are still not sent to the new one.
* Dev - Checked against WooCommerce 11.3 (beta 1): the Checkout block's consent box is still never shown ticked. WooCommerce 11.3 reads a checkbox nobody answered as "not set" (an empty string) instead of `false` ([woocommerce#68780](https://github.com/woocommerce/woocommerce/pull/68780)); the plugin only treats an explicit `true` as consent, so nothing changes for shoppers or merchants. The integration test now checks that the answer is removed from the profile instead of the exact empty value.
* Dev - CI (PHPCS, PHPStan level 8, JS build, PHPUnit unit/contract/integration with HPOS on and off, Plugin Check, Playwright checkout e2e) and release pipeline.
* Add - Self-hosted builds update from the plugin's GitHub releases: the latest stable release's `*-selfhosted.zip` asset (pre-releases and releases without that asset are skipped). Filter `pixalink_loyalty_update_repository_url` points it at another repository. CI and releases run on GitHub-hosted runners.
